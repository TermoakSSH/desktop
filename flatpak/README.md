# Flatpak

`com.termoak.Termoak`, built from source on the Freedesktop runtime with the
`rust-stable` SDK extension.

| File | What |
|------|------|
| `com.termoak.Termoak.yml` | Manifest: the `desktop-vX.Y.Z` tag (and its commit), the sandbox permissions and the build |
| `cargo-sources.json` | Every crate of that tag's `Cargo.lock` (crates.io archives and the TermoakSSH/core git checkout), so the build runs offline; generated by `update-sources.sh` |
| `patches/desktop-v0.6.0-flatpak.patch` | Flatpak support that 0.6.0 lacks, from `main` (see below); only for 0.6.0 |
| `update-sources.sh` | Regenerates `cargo-sources.json` with flatpak-builder-tools' `flatpak-cargo-generator` |

The desktop entry, the AppStream metadata and the icons are in
`assets/linux/` (shared with the AppImage and the Linux tar.gz).

Where it is published:

- **pkg.termoak.com/flatpak**, the Termoak repository, signed with the
  package key: built and deployed by
  [TermoakSSH/packages](https://github.com/TermoakSSH/packages)
  (`scripts/publish.sh --only flatpak`, which builds this directory of
  `main`).
- **Flathub**: prepared, not submitted. Steps in
  [packages/docs/flathub](https://github.com/TermoakSSH/packages/blob/main/docs/flathub/README.md).

## In the sandbox

- The app's own updater is off (`src/flatpak.rs`, `src/update.rs`): Flatpak
  updates it, and Settings → Updates says so instead of offering "Check for
  updates". The build has no `TERMOAK_UPDATE_PUBKEY` either.
- The local terminal runs the user's login shell on the host with
  `flatpak-spawn --host` (hence `--talk-name=org.freedesktop.Flatpak`).
- Files: the SFTP downloads go to `~/Downloads` (`--filesystem=xdg-download`);
  any other folder through the file chooser portal; `~/.ssh` read-only for
  "Import ~/.ssh/config" and its `IdentityFile` keys. No access to the rest
  of the home folder.
- The SSH agent (`--socket=ssh-auth`), the keychain (Secret Service) and
  notifications over D-Bus.
- Serial ports are not exposed (`--device=dri` only); a user who needs them:
  `flatpak override --user --device=all com.termoak.Termoak`.
- Data lives in `~/.var/app/com.termoak.Termoak/data/termoak` instead of
  `~/.local/share/termoak`; copy it over (with the app closed) to keep the
  hosts of "This device" from a package or AppImage install. The vault key
  is the same keychain entry.
- Local AI agents (Codex, Claude Code... CLIs) installed on the host are not
  visible from the sandbox; the AI with your own API keys works.

## New release

1. In `com.termoak.Termoak.yml`: `tag: desktop-vX.Y.Z` and its `commit`.
2. `flatpak/update-sources.sh` (reads the tag from the manifest).
3. The `<release>` in `assets/linux/com.termoak.Termoak.metainfo.xml` (before
   tagging) and the screenshot URLs at the new tag.
4. Drop the `patches/desktop-v0.6.0-flatpak.patch` source once the tag
   contains it (any tag after 0.6.0).
5. Build and publish from TermoakSSH/packages:
   `flock /root/.termoak-build.lock scripts/publish.sh --only flatpak --deploy /var/www/pkg.termoak.com`.

The 0.6.0 patch is `git diff --binary --full-index desktop-v0.6.0 <commit> --
src locales assets` of the commit that added the Flatpak support, applied
with `git apply` (`use-git: true`, it carries the PNG icons).
